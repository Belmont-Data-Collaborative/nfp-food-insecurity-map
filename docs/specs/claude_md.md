## Architecture rules (do not break these)

These invariants are from `CLAUDE.md` and are critical:

- **`project.yml` is the single source of truth** for indicator metadata, partner types, and palettes. Edit `project.yml` first, then run `--step export`. Never edit `data/config.json` directly — it is generated.
- **`data/` is gitignored** and regenerated by the pipeline. Do not commit files under `data/`.
- **No build step.** The site is static HTML/CSS/JS. Do not introduce npm, a bundler, or TypeScript.
- **No Streamlit, no Folium, no Branca.** These are explicitly excluded.
- **GEOID zero-padding must be preserved** throughout any pipeline changes.
- **Both point GeoJSONs use `partner_type`** (not `category` or `name`). Do not change this key.
- **`health_lila_*` → `health_*` rename** in `export_csv.py::STEM_RENAMES` must stay — the frontend hardcodes the short names.

## How to test locally

```bash
# One-time setup (if not already done)
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # keep USE_MOCK_DATA=true

# Seed mock data
python scripts/generate_mock_data.py
python scripts/generate_mock_parquet.py

# Run pipeline (mock mode)
python -m pipeline

# Serve
python -m http.server 8000
# Open: http://localhost:8000/Map.html
```

For frontend-only changes (Items 1–5), no pipeline run is needed — just serve and refresh.

For `project.yml` changes (Items 4a, 6a, 8a), run `python -m pipeline --step export` before serving.

For pipeline changes (Items 7, 8), run `python -m pipeline --step partners` (and `--step giving_matters` if you touched that processor).

## Acceptance criteria checklist

Both spec files contain complete acceptance criteria tables. Work through them top-to-bottom using `http://localhost:8000/Map.html` before opening a PR.

Critical checks to do in your browser:
1. Hard-refresh (`Ctrl+Shift+R`) after any `project.yml` → `config.json` regeneration.
2. For sticky-hover fix: move mouse quickly across tracts before and after your change.
3. For clustering fix: zoom to 13 over downtown Nashville and confirm no cluster bubbles remain.
4. For LILA default: open Map.html in a new incognito window (no cached tweaks).
5. For geo-toggle guard: switch to ZIP Codes with LILA active; confirm auto-switch to Median Household Income.

## Deployment (after merge and approval)

```bash
# Regenerate config after project.yml changes
python -m pipeline --step export

# Upload data outputs to S3 (data pipeline spec only)
python -m pipeline --step partners
aws s3 sync data/ s3://nfp-food-insecurity-map-data/current/ --exclude "mock/*"

# Push and deploy
git push origin main
vercel --prod --scope databelmonts-projects
```

Both buckets have distinct roles — do not confuse them:
- `bdaic-public-transform` — SOURCE inputs (pipeline reads)
- `nfp-food-insecurity-map-data` — OUTPUT (pipeline writes, Vercel reads, under `current/` prefix)
